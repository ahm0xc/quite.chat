# PWA Plan for Quite Chat

## Overview

Add PWA support (installable app, offline shell caching) and push notifications (background alerts when the app isn't focused) to the existing TanStack Start + Vite+ app.

---

## Phase 1: PWA Foundation

### 1.1 Install dependency

```bash
bun add -D vite-plugin-pwa
```

### 1.2 Add to `vite.config.ts`

Configure `VitePWA` plugin with:

- `registerType: 'autoUpdate'` — auto-reload when new SW available
- `workbox` config: cache the app shell, static assets, and API routes with network-first strategy
- `manifest` inline or via `manifest.json` in `public/`

### 1.3 Create `public/manifest.json`

```json
{
  "name": "Quite Chat",
  "short_name": "Quite",
  "description": "A quiet space to chat",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#000000",
  "theme_color": "#000000",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" },
    {
      "src": "/icon-512.png",
      "sizes": "512x512",
      "type": "image/png",
      "purpose": "maskable"
    }
  ]
}
```

### 1.4 Generate app icons

Create 192x192 and 512x512 icons (use existing branding or a simple letter mark). Place in `public/`.

### 1.5 Update `src/routes/__root.tsx`

Add to `<head>`:

- `<meta name="theme-color">`
- `<meta name="apple-mobile-web-app-capable">`
- `<link rel="apple-touch-icon">`
- `<link rel="manifest">` (if not auto-injected by plugin)

### 1.6 Workbox caching strategies

| Route                           | Strategy                     |
| ------------------------------- | ---------------------------- |
| Static assets (JS, CSS, images) | `CacheFirst` with expiration |
| App shell (`/`)                 | `NetworkFirst` with fallback |
| API routes (`/api/*`, tRPC)     | `NetworkOnly` (always fresh) |
| CDN assets                      | `StaleWhileRevalidate`       |

## Phase 2: Push Notifications

### 2.1 Database — store push subscriptions

Add to `src/db/schema.ts`:

```ts
export const pushSubscriptions = pgTable("push_subscriptions", {
  id: serial("id").primaryKey(),
  userId: text("user_id").notNull(), // Clerk user ID
  endpoint: text("endpoint").notNull(),
  p256dh: text("p256dh").notNull(),
  auth: text("auth").notNull(),
  createdAt: timestamp("created_at").defaultNow().notNull(),
});
```

### 2.2 Generate VAPID keys

One-time setup. Store in `.env`:

```bash
bunx web-push generate-vapid-keys
```

Add to `env.ts`:

- `VAPID_PUBLIC_KEY` (exposed to client)
- `VAPID_PRIVATE_KEY` (server only)
- `VAPID_SUBJECT` (your email, e.g. `mailto:you@example.com`)

### 2.3 Server — tRPC endpoints

Create `src/server/routers/push.ts` with:

| Procedure          | Purpose                                                                                |
| ------------------ | -------------------------------------------------------------------------------------- |
| `subscribe`        | Store the user's push subscription in DB                                               |
| `unsubscribe`      | Remove subscription by endpoint                                                        |
| `sendNotification` | Send a push to a specific user (server-side, triggered by app events like new message) |

Use `web-push` package:

```bash
bun add web-push
```

### 2.4 Client — subscribe to push

After user grants permission:

```ts
const registration = await navigator.serviceWorker.ready;
const subscription = await registration.pushManager.subscribe({
  userVisibleOnly: true,
  applicationServerKey: VAPID_PUBLIC_KEY,
});
// Send subscription to server via tRPC push.subscribe
```

### 2.5 Service worker — handle push events

In the SW file (generated by vite-plugin-pwa or a custom `public/sw.js`):

```ts
self.addEventListener("push", (event) => {
  const { title, body, icon, data } = event.data.json();
  event.waitUntil(
    self.registration.showNotification(title, { body, icon, data }),
  );
});

self.addEventListener("notificationclick", (event) => {
  event.notification.close();
  event.waitUntil(
    clients.matchAll({ type: "window" }).then((clientList) => {
      // Focus existing tab or open new one to notification URL
      if (clientList.length > 0) {
        clientList[0].focus();
      } else {
        clients.openWindow(event.notification.data?.url || "/");
      }
    }),
  );
});
```

### 2.6 Trigger notifications on events

When a new message is sent in a chat, call `sendNotification` for each offline recipient:

- Check if user is currently online (Pusher presence or last seen timestamp)
- If offline or app not focused, send push
- Skip sending to the message sender

## Phase 3: iOS Home Screen Prompt

### 3.1 Detect platform

```ts
const isIOS =
  /iPad|iPhone|iPod/.test(navigator.userAgent) && !window.navigator.standalone;
const isStandalone =
  window.matchMedia("(display-mode: standalone)").matches ||
  window.navigator.standalone;
```

### 3.2 Show install CTA on iOS

If `isIOS && !isStandalone`:

- Show a banner or modal: "Add Quite to your Home Screen to receive notifications"
- Include step-by-step instructions (Share → Add to Home Screen)
- Only show once, store dismissal in localStorage

### 3.3 Show install prompt on desktop/Android

Use the browser's `beforeinstallprompt` event:

- Intercept the event, store it
- Show a custom "Install App" button
- On click, call `event.prompt()`

### 3.4 Handle after install

After installation, immediately request notification permission — the user just committed to the app, highest conversion moment.

## Phase 4: Polish

### 4.1 Notification settings UI

- Add a toggle in user settings: "Push notifications on/off"
- Shows current permission status
- "Test notification" button
- Per-chat mute option (store in existing settings or a new table)

### 4.2 Offline indicator

- Listen to `navigator.onLine` / `offline` events
- Show a subtle banner when offline: "You're offline — messages will send when reconnected"
- Already partially handled by Dexie offline-first pattern

### 4.3 Update prompt

- When a new SW is installed, show: "New version available — refresh to update"
- Use `vite-plugin-pwa`'s built-in `prompt` strategy

## What we already have that helps

- **Dexie (IndexedDB)** — app already handles offline data, service worker just caches the shell
- **Clerk** — user identity for per-user subscriptions
- **tRPC** — wire up subscribe/send endpoints cleanly
- **Drizzle + Postgres** — store subscriptions
- **Pusher** — complement with background push when user is away
- **TanStack Router** — file-based, `__root.tsx` is the single HTML entry for meta tags

---

## Implementation order

1. PWA foundation (manifest, icons, SW, caching) — app becomes installable
2. Push subscription flow (DB, VAPID, tRPC, client subscribe) — plumbing ready
3. Push trigger on new messages — notifications actually send
4. iOS/desktop install prompts — users discover PWA
5. Settings UI — users control notifications
6. Offline indicator + update prompt — polish
